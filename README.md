# Дипломный проект - Онлайн‑площадка для продажи и перепродажи вещей.

### Платформа предоставляет пользователям инструменты для публикации и администрирования объявлений. В функционал входят регистрация и авторизация, возможность комментирования публикаций, а также загрузка и обработка изображений. Пользователи сервиса могут размещать объявления, вносить в них изменения и изучать профили других пользователей.

---
## Используемые технологии

* **Язык:** Java 17
* **Фреймворк:** Spring Boot 3.2.5
* **Сборщик проекта:** Apache Maven 3.9+
* **База данных:** PostgreSQL 13+
* **Миграции:** Liquibase
* **Документация API:** Swagger UI 
* **Библиотека для упрощения кода:** Lombok 
* **Библиотека для маппинга DTO:** MapStruct 1.5.5.Final
* **Аутентификация и авторизация:** Spring Security
* **Фронтенд:** React (Docker)
---
## Применение Liquibase
Миграция схемы базы данных осуществляется автоматически при старте приложения с помощью **Liquibase**.

*   Файлы миграций расположены в папке: `src/main/resources/db/changelog`.
*   При первом запуске Liquibase создаст все необходимые таблицы, индексы и связи согласно файлам changelog.
*   Не требуется ручного выполнения SQL-скриптов для создания структуры таблиц — достаточно создать пустую базу данных (см. раздел «Запуск работы приложения» п.2) и запустить приложение.

## Запуск приложения
1. Клонируйте репозиторий: `git clone <ваш-репозиторий>`.
2. Создайте базу данных и пользователя:
```SQL-скрипт для создания базы и пользователя:
CREATE DATABASE skypro_ads;

CREATE USER username WITH PASSWORD 'password';

GRANT ALL PRIVILEGES ON DATABASE skypro_ads TO username;
```

Или с другими названиями базы данных и пользователя, но в таком случае необходимо изменить в файле `application.yml` данные (имя базы данных, имя пользователя и пароль).
3. Запустите фронтенд (Docker):
    ```bash
   docker run -p 3000:3000 --rm ghcr.io/dmitry-bizin/front-react-avito:v1.21
   ```
4. Запустите бэкенд: `mvn spring-boot:run`.
5. Перейдите в браузере по ссылке: `http://localhost:3000/`

## Порядок проверки основных функций
Чтобы убедиться, что приложение работает корректно, выполните следующие шаги:
### 1. Проверка API и документации
1. Откройте в браузере: [http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html).
2. Убедитесь, что отображается список всех доступных эндпоинтов.
3. Протестируйте несколько методов прямо из Swagger UI (например, регистрацию или получение списка объявлений).
---
### 2. Регистрация и авторизация
1. Отправьте POST‑запрос на регистрацию нового пользователя (через Swagger или Postman).
2. Попробуйте выполнить запрос к защищённому ресурсу (например, получить список своих объявлений).
3. Убедитесь, что без авторизации доступ к защищённому ресурсу запрещён (статус `401 Unauthorized`).
3. Авторизуйтесь для дальнейших запросов.
---
### 3. Работа с объявлениями
1. Создайте объявление с помощью POST‑запроса:
    * Передайте данные объявления (заголовок, описание, цена и т. д.).
    * Прикрепите файл изображения (multipart/form-data).
2. Проверьте, что:
    * Файл сохранился в настроенной папке (например, `/tmp/ads-images`).
    * Путь к файлу корректно записан в базе данных.
3. Отредактируйте объявление с помощью PUT/PATCH‑запроса и убедитесь, что изменения применились.
### 4. Работа с комментариями
1. Добавьте комментарий к чужому объявлению и проверьте, что он отображается в списке комментариев.
2. Попробуйте удалить или изменить свой/чужой комментарий к объявлению.
---
### 5. Проверка фронтенда
1. Откройте фронтенд в браузере: [http://localhost:3000](http://localhost:3000).
2. Проверьте взаимодействие фронтенда с бэкендом:
    * Регистрация и авторизация (отдельно с ролями администратора и простого пользователя)
    * Редактирование аватарки пользователя.
    * Редактирование данных и пароля пользователя.
    * Создание объявления.
    * Просмотр списка объявлений.
    * Редактирование и удаление объявлений (только для своих объявлений или для всех, если пользователь администратор).
    * Создание комментария к объявлению.
    * Редактирование и удаление комментариев (только для своих комментариев или для всех, если пользователь администратор).
3. Убедитесь, что загруженные изображения корректно отображаются на странице объявления.

## Тестирование
В проекте реализовано unit-тестирование контроллеров с использованием Spring Boot Test и JUnit 5.

### Количество тестов
Всего создано **13 тестов** для проверки работоспособности контроллеров:

| Контроллер | Количество тестов | Описание |
| :--- | :--- | :--- |
| `AdController` | 2 | Тесты для получения списка объявлений |
| `AuthController` | 4 | Тесты для авторизации и регистрации |
| `UserController` | 3 | Тесты для управления профилем пользователя |
| `CommentController` | 4 | Тесты для работы с комментариями |

### Структура тестов
Тесты расположены в папке: `src/test/java/ru/skypro/homework/controller/`

**Файлы тестов:**
- `AdControllerTest.java` — тесты эндпоинтов объявлений
- `AuthControllerTest.java` — тесты авторизации и регистрации
- `UserControllerTest.java` — тесты управления пользователем
- `CommentControllerTest.java` — тесты работы с комментариями

### Как запустить тесты
Для запуска всех тестов выполните команду:
```bash
./mvnw test
```

Для запуска конкретного тестового класса:
```bash
./mvnw test -Dtest=AdControllerTest
```

### Покрытие тестами
Тесты проверяют:
- Корректность возвращаемых HTTP-статусов
- Правильность сериализации DTO объектов в JSON
- Обработку валидации входных данных
- Публичные эндпоинты (GET /ads, login, register, set_password и др.)
